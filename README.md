# TrustVault

Secure document sharing where **the server decides on every request** who may reach a file, and every reach (or refused attempt) is written to a tamper-evident audit log.

Stack: Python 3.12, Flask, SQLite (stdlib), vanilla JS front end (no build step). Chosen because the whole system runs from a clean clone with `pip install -r requirements.txt`, and because an audit append and the action it records can be one SQL transaction.

## Demo accounts (seed data, created on first start)

| Role | Username | Password | Can |
|---|---|---|---|
| Administrator | `admin` | `Admin#Vault2026` | manage users, see metadata/audit/alerts. **Cannot open documents** |
| Document owner | `alice` | `Alice#Vault2026` | upload, share, revoke, delete own documents |
| Document owner | `bob` | `Bob#Vault2026!` | same, own documents |
| Viewer | `carol` | `Carol#Vault2026` | only what she is granted (read on *Salary letter - Carol*) |
| Viewer | `dave` | `Dave#Vault2026!` | read on *Salary letter - Dave*, edit on Bob's *Partner drawings* |

Override any password with `TV_SEED_PW_<USERNAME>`. **Change/disable these on any real deployment.**

Try it: sign in as `carol`, see one document. Sign in as `alice`, open *Salary letter - Carol*, press **Revoke**; carol's next click fails immediately. Sign in as `admin` -> **Audit**: the refusal is there; press **Verify integrity**.

## Run locally

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -c "from wsgi import application; application.run(port=8000)"   # seeds on first start
# open http://localhost:8000
```
Data lives in `./instance` (SQLite db, random-named blobs, `audit.key`). Delete that folder to reset.

## Tests

```bash
python -m unittest discover -s tests -t .       # 45 tests, ~3 s
python scripts/mutation_check.py                # removes 21 security controls one by one; each MUST make the tests fail
```
The mutation script is the answer to "what if one authorisation check is removed?": it does exactly that and reports any removal the tests survive. (On the first run 3 survived; see PROMPTS.md.)

## Deploy (Render, Docker)

1. Push the repo to GitHub; in Render choose **New -> Blueprint** and select it (`render.yaml`), or create a Docker web service.
2. `TV_AUDIT_KEY` is generated by the blueprint. Keep it: if it changes, old audit records no longer verify.
3. Free plans have an **ephemeral disk**: data resets on restart. For anything real attach a persistent disk at `/data`.
4. Seeded demo users appear on first boot. Open the URL in a private window and log in with the table above.
Any container host works: `docker build -t trustvault . && docker run -p 8000:8000 -e TV_SECURE_COOKIES=0 -e TV_AUDIT_KEY=$(openssl rand -hex 32) -v tv:/data trustvault`.

## Layout

```
app/authz.py      THE document authorisation decision (read this first)
app/audit.py      HMAC hash-chained append-only log + verifier
app/security.py   sessions, CSRF/Origin, role gate
app/api.py        document, sharing, auth routes      app/admin.py  admin routes
app/storage.py    upload validation, random-name blob storage
schema.sql        database schema (applied automatically at start-up)
scripts/seed.py   demo data        scripts/mutation_check.py   test-the-tests
tests/            security tests (T-n ids match THREATS.md)
THREATS.md  API.md  WRITEUP.md  PROMPTS.md
```

## Where is the authorisation decision made when someone downloads a file?
`app/api.py: download()` -> `authz.authorize(db, user, doc_id, "read", "document.download")` -> `authz.get_access()`. If that call were removed, the mutation check shows tests T2/T3/T4/T9 fail. Nothing else (no URL, token, or cache) grants file access.
